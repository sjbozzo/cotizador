COTIZADOR EDGE AI — INSTRUCCIONES DE LA TAREA
=============================================

Objetivo del proyecto
---------------------
Construir un dispositivo de borde que:
  1. Se conecte a un router local y reciba el video de VARIAS cámaras IP (RTSP/ONVIF, H.264/H.265, 1080p).
  2. Corra YOLO (v5/v8/v11) sobre esos flujos en el mismo equipo.
  3. Envíe sólo las detecciones (metadatos) a la nube.

Ideal: un solo equipo encapsulado en aluminio (o con carcasa de aluminio disponible), menos de US$500 el
nodo completo, comprable desde Chile con disponibilidad alta (stock real, vendedor confiable, envío a Chile
o venta local) y fácil de programar (Linux, SDK maduro, ejemplo YOLO oficial, Python/C++). US$1 ≈ CLP $950.

La aplicación (FastAPI + SQLite) sirve para comparar candidatos por familia y tomar esa decisión.
Ver README.md para levantarla (`uv sync` y `uv run uvicorn app.main:app --reload`).

Criterios de veredicto
----------------------
  keep    = sirve para el nodo o es el acelerador/carcasa/servicio que el nodo necesita.
  discard = existe pero no encaja (caro, sin stock, ecosistema muerto, no corre YOLO, M.2 inservible).
  delete  = error del catálogo: inexistente, duplicado, fuera de categoría, o pedido explícito del usuario.
Una baja propuesta por un agente sólo se aplica si la revisa una persona (o al menos dos jueces).

Mezcla de las dos versiones (2026-09-03)
---------------------------------------
Dos IA resolvieron por separado el mismo encargo y quedaron dos exportaciones HTML distintas: una con
ocho ítems por cotización, más candidatos y mejores precios, pero sin fotos ni las columnas nuevas; y
otra con pocos ítems (3/4/1/6/4) pero muy verificados, con fotos embebidas, página del fabricante y nota

candidatos de la primera, y se dejaron CINCO ítems por cotización.

Reglas que impone la mezcla (las verifica scripts/merge_ai_versions.py y falla si alguna se rompe):
  - Cinco ítems por cotización, todos con foto embebida en la base (no dependen de la URL del vendedor).
  - Ningún campo vacío, estimado ni incompleto: cada precio dice fuente y fecha.
  - Nota de durabilidad + confiabilidad de 1 a 10, justificada con hechos (rango térmico, certificaciones,
    garantía, compromiso de producción, refrigeración).
  - Columna «Página del fabricante», siempre distinta del link de compra.
  - Máximo dos ítems de la misma marca y máximo cuatro del mismo país por cotización.
  - Todo link abre y el producto llega a Chile; el flete se cotizó de verdad (carrito con dirección en
    Santiago, código postal 8320000) donde la tienda lo permite.

Hallazgos que corrigieron datos anteriores:
  - AMD Kria KV260: la cifra baja es real y la publica AMD. El product brief del K26 dice «up to 1.4TOPS»
    y la imagen que viene con el KV260 usa un DPU B3136 de 0,92 TOPS pico / 0,25 efectivos. Se descartó y
    se pusieron dos equipos con silicio AMD de verdad (Ryzen AI 9 HX 370 de 50 TOPS y Ryzen 7 8845HS de 16).
  - La NPU de AMD no tiene camino soportado en Linux: el driver amdxdna entró en Linux 6.14, pero el stack
    oficial (ONNX Runtime + Vitis AI EP) está documentado sólo para Windows 11. En un nodo Linux la
    inferencia cae en la iGPU o la CPU. Queda dicho en la ficha de ambos equipos AMD.
  - FriendlyELEC NanoPC-T6-LTS: NO despacha a Chile (su propio módulo de envío responde «No Shipping
    options are available» y Amazon lo rechaza con dirección chilena). Estaba dado por bueno; se sacó.
  - Hailo-8L M.2 y el stick USB Hailo-10H de AAEON: sin canal que llegue a Chile (UP Shop lista sus 57
    destinos y Chile no está). Reemplazados.
  - MeLE Quieter 4C: puesto en Chile queda sobre US$450, así que el nodo pasa de US$500. Se descartó.

Cómo continuar
--------------
Los flujos de agentes están en scripts/auditoria/workflows/ y se ejecutan con el comando Workflow de
Claude Code. Cuidado: cada agente con búsqueda web cuesta mucho; el flujo pesado agotó el límite de sesión
de la cuenta dos veces. Usar la versión ligera:
  1. Armar lotes de 4 ítems: `uv run python -m scripts.prepare_audit_batches <carpeta> --skip edge-ai-aceleradores-m2`
     (escribe `lotes/*.json` y `lean-args.json`; cada lote trae id, nombre, precio, textos y claves de columnas
     extra). Omitir con --skip las cotizaciones ya auditadas.
  2. Lanzar `auditar-lean.js` con args {brief: <texto corto del brief>, batches: [{q, file, names}]}.
  3. Guardar el resultado en scripts/auditoria/AAAA-MM-DD-auditoria-lean.json.
  4. Revisar a mano cada baja (verdict discard/delete): si la evidencia es sólida, marcar el ítem con
     "votes": "revisado"; si no, dejarlo (se mantiene).
  5. Aplicar: `uv run python -m scripts.apply_audit <archivo.json> --dry-run` y luego sin --dry-run.
     Es idempotente: se puede volver a correr.
Alternativa más barata: verificar a mano ítem por ítem (WebSearch/WebFetch), escribir el resultado en el
mismo formato JSON (ver 2026-09-02-m2-en-linea.json como ejemplo mínimo) y aplicarlo igual.

Para agregar candidatos: escribir un JSON con {"quotations": [{"quotation_id", "picks": [...]}]} en el
formato de 2026-09-02-candidatos-revisados.json y aplicarlo con el mismo script.
